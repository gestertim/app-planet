### 帳號、權限與安全約束

所有使用者需註冊並經管理員批准。帳號狀態：待審核、已批准、已拒絕、已停用。待審核只能查看申請狀態及登出；拒絕可查看結果與說明；停用不可使用受保護功能。管理員核定角色及師生關係；使用者不可自行提升權限。

學生管理自己的資料；教師僅查看獲授權學生紀錄及審查；管理員管理平台。專案、對話、檔案預設私人，公開須走授權流程。每次受保護操作都驗證即時帳號狀態、角色與資源權限；背景工作開始及重要步驟也須重新驗證。

密鑰不進前端、學生作品、下載檔或紀錄。不受信任程式隔離執行，限制資源、時間、工具及網路；預覽使用獨立來源。外部內容與 Skills 不得繞過權限或批准。

用量採原子預留、執行、結算、釋放餘額；限制個人用量、頻率、並行及總費用；重試冪等，結果不明須核對。管理、Agent、部署操作保留適當稽核。

### UX-07 建立 App

### UX-08 版本、審查與發布

恢復前先保存目前工作；快照保存失敗即停止恢復。提交部署時固定不可變版本及內容雜湊。教師審查呈現該申請版本的藍圖、預覽、測試結果、變更及回饋，不得以目前工作預覽替代申請版。

審查操作為批准部署／退回修改。正式狀態區分尚未提交、待審查、退回修改、已批准、部署中、部署成功、部署失敗。批准不等於部署成功。成功才顯示對應網址；失敗保留原公開版本。修改後須重新申請；工作區編輯不自動更新公開版本。

### UX-09 教師、管理員與帳號

教師工作區：真實所屬學生、創作專案、進度、授權紀錄、回饋及待審查部署。管理中心：申請審核、角色、師生關係、停用、額度、安全與操作紀錄。回饋、審查理由及綁定變更必須真正保存且可重新讀取。

註冊狀態為待審核／已批准／已拒絕／已停用，各有明確畫面。待審核只能查看狀態及登出；拒絕顯示結果及說明；停用不得使用受保護功能。申請角色不等於取得權限。

正式版帳號區只提供已授權身份及操作；原型的學生／教師／管理員自由切換限展示環境，不是正式權限設計。不可透過顯示或隱藏導覽代替後端授權。

### UX-10 創作能量、保存及錯誤

「創作能量」為用量資訊，不做排行榜或催促消耗。顯示剩餘／可用、預留中與適用期間；數據來自實際政策及服務端。無法查詢時顯示未知，不沿用假百分比。82%、100 次、同時 2 件等均為示例，不能自動寫成正式政策。

| 狀態 | 必要表現與恢復 |
| --- | --- |
| 空白／無結果 | 說明目前沒有內容，提供建立或調整搜尋入口。 |
| 保存中／已保存 | 與真實保存結果一致；有未保存修改須顯示。 |
| 保存失敗／離線 | 保留草稿、提示原因與手動重試，不能仍固定顯示已儲存。 |
| AI／Agent 中斷 | 保留已完成部分、列明未完成項目，提供恢復選擇。 |
| 額度不足／頻率限制 | 說明受影響操作，既有保存內容仍可查看；重試不重複扣額。 |
| 帳號／權限變更 | 更新可用操作與提示；不繼續未授權工作。 |
| 部署失敗 | 顯示失敗版本及下一步，保留原公開版。 |

### UX-11 響應式與可及性

所有操作可用鍵盤；焦點可見。彈窗開啟移入焦點、限制於彈窗內、關閉回到觸發點；Esc 關閉可取消彈窗。圖示按鈕有名稱，進度與錯誤可被輔助工具讀取。新對話快捷鍵顯示符合系統的 ⌘K／Ctrl+K，觸發時同樣保護草稿。

## 從目前狀態出發的最短操作

1. 開啟正式平台 repository，貼第①段查明現況。
2. 已有 Constitution 就核對沿用；已有本功能規格就用第③段既有功能同步，否則首次 Specify。
3. 執行第④段 Clarify，回答並寫回待決政策。
4. 貼第⑤段，保存 UX/UI 並完成實際規格同步。
5. 更新 Plan、通過 Checkpoint，再 Checklist → Tasks → Analyze。
6. 通過 Readiness Gate，取得具體階段實作批准後 Implement → Verify；需要時 Converge。

如果尚無開發 repository，先建立獨立正式專案目錄並完成工具準備；不要把目前 Sites 靜態模擬站直接認定為正式全端平台。
