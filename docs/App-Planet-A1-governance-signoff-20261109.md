### 2.1 AUTH §2(1)：原文 → 建議修文

**原文**（[AUTH §2「登入流程不變式」第 1 項](../specs/001-app-planet-platform/contracts/auth-and-identity.md)）：

> 1. **不洩漏帳號是否存在**：未知 `handle`、錯誤碼、已被取代的舊碼、（停用或標記刪除帳號的）錯誤碼，回應本文、狀態碼、標頭、耗時分佈需不可區分（未知帳號仍執行等價的雜湊與 Auth 呼叫耗時）；**節流本身也不得洩漏**：節流桶以 `HMAC(handle)` 為鍵，不論帳號是否存在，相同嘗試次數下同時進入 `429`（S-02）。

**建議修文**（只替換此項；待核准）：

> 1. **不洩漏帳號是否存在**：未知 `handle`、錯誤碼、已被取代的舊碼、（停用或標記刪除帳號的）錯誤碼，回應本文、狀態碼、標頭、耗時分佈需不可區分（未知帳號仍執行等價的雜湊與 Auth 呼叫耗時）；**節流本身也不得洩漏**：以「正規化 `handle` × 可信來源」的 HMAC 配對鍵設桶，另設可信來源 HMAC 桶，不保存原始帳號或 IP。於相同初始桶狀態、相同可信來源與相同嘗試序列下，不論帳號已知或未知，配對限流必須在相同嘗試次數觸發 `429`。來源 A 的配對鎖定不得連帶封鎖來源 B 對同一帳號的登入；來源 B 的正確碼仍須通過其自身配對桶、來源桶、上游限流及其他登入資格檢查，不因跨來源或正確碼而繞過限制。來源 A 的節流須為可恢復的漸進延遲，非永久硬鎖；`429` 附 `Retry-After`。帳號列舉防護與正式 S-02 全部驗收要求保留。

**語意對照與不變界線**：

- [AUTH A-1](../specs/001-app-planet-platform/contracts/auth-and-identity.md) 已列「帳號雜湊×IP 雜湊、IP 雜湊」兩層限流；配對鍵的來源必須由可信來源驗證取得，不直接相信 caller 的 forwarded／proof 標頭。配對 HMAC 的組合須無歧義；不能退回會跨來源拒絕的全域 handle 鎖。全域 handle 統計不作登入拒絕桶。
- [S-02-3](../specs/001-app-planet-platform/quickstart.md) 的 IP-A／IP-B 要求不變：在 B 自身及上游未超限、資格有效的測試前提下，A 輸錯到配對限流，B 用同一學生正確碼成功，A 仍依漸進延遲；另驗 B 自身超限時確實 429。不得為了宣稱 B 成功而忽略來源桶或上游限制。
- 已知錯碼／未知帳號同來源同序列，須比較桶計數與 HTTP／problem／標頭／耗時，不能只用 dummy 呼叫或固定 sleep 聲稱不可區分；真 Auth 與受控 adapter 的證據分列，上游非對稱必須如實呈報，不改寫為通過。
- 正式 S-02-1～6 保留：IP 轉送／供應商來源處理、同 NAT 30 位於 60 秒內 30/30 與 30 IP 對照、跨來源輸錯、HMAC 去敏，以及各類錯誤至少 200 次、事前核定 p50／p95 容許差等。**本批不執行正式 S-02**，不以小樣本、revoked 案或隔離值替代；S-01／S-03 亦不轉為已驗。
- 這是正式契約的桶鍵修正，不是只限本批的秘密解釋；不變更正式 PP-03 數值／T1 時點、供應商、A-2 契約、核發／重發及 D-32。

### 3.2 生效後才可執行的完整有界範圍

- **最小消費端**：依鎖定修正版 §1～§3 建立最小 credential 投影／受限 lookup 與必要新編號 migration、欄位 grants、FORCE RLS／policy、獨立低權限 login role；不改既有已套用 migration、不以 service-role 全表讀取替代。實測 owner 非底表擁有者／不 bypass、PUBLIC／anon／authenticated／一般 runtime 無直讀或 EXECUTE、無角色繼承／SET ROLE 升權與寫入能力。
- **合成 fixture**：僅測試控制層的隔離 Auth admin／DB 控制連線建立，不寄信；先取得可信 Auth 建立回應 UUID，再寫 profile／credential 並讀回核對。合成碼、alias、token／cookie 值不進文件、日誌、storage、trace／HAR／截圖；產品不持控制憑證、不匯入 test fixture、不設核發後門。
- **A-1 API／真表單**：strict `{handle,login_code}`、正規化／原始 bytes 上限、可信來源、雙層 HMAC 節流、可信 Auth 驗 UUID、DB 當下本人／學校 gate、發 cookie 前重讀與固定 `/student` 導向；600 秒設定及安全 cookie／到期拒絕須實驗證，不使用 refresh。未知／錯碼／非學生／revoked 不取得學生 session；有效憑證的 pending／rejected 亦 403，不借用 A-2 的受限 session 語意。
- **主驗收，不可用注入 session 代替**：新 browser context 先斷言 cookie 為空 → 真學生表單輸入合成 handle／碼 → 真 A-1 Auth＋DB＋HTTPS cookie → `/student` → 明確輸入點子、帶入新作品並建立 → 首次手動保存 → reload。核對同一 project 的點子 `stage_records` 保存前 0 筆、後 1 筆 version 0，`content.text` 與輸入逐字相等（含換行／尾空格），reload UI／DB 一致。證據只保存去敏計數與相等結果，不以截圖代替保存證明。
- **拒絕及節流聚焦驗收**：依修正版矩陣涵蓋未知／錯碼、正確碼但 pending／rejected／disabled／刪除狀態、學校 unconfirmed、非學生入口、lookup／UUID／依賴故障、來源偽造、欄位 128／129 與 body 4096／4097 bytes、HTTP＝problem.status＝登錄 status、429／Retry-After、已知／未知同來源同序列與 A／B 配對鎖定；withdrawn／expired 仍依既有 gate 保存，不放行 AI／公開部署。
- **明列非正式證據**：revoked 只驗「同碼先成功→產品登出清空→控制層改 revoked 並讀回→同碼 401」，不是重發／Auth 密碼撤銷。缺校只以成功受控 reader 的 `school_found=false` 驗 403；真 DB 缺校受 CHECK／FK 阻擋，標未驗，不拆約束；reader 故障仍 503。受控情境與真 Auth／DB 結果分列。
- **A-2 回歸**：approved teacher／admin 各自導向、pending／rejected 受限頁、disabled／刪除拒絕、student 經 A-2 401；既有 cookie、登出、欄位 400／額外欄位 422／整體 413、文案及 HTTP／problem 一致性不退化。依變更面執行最小 unit／contract／真 Auth＋DB／HTTPS browser；不將歷史數字當本批結果。
- **隔離與交付**：只啟動必要獨立本機 Auth／PostgreSQL／單 Next HTTPS／可信來源 proxy；與展示環境／共享資源不重疊，缺設定拒啟。若確需安裝，首次安裝前即在同程序設定並核對本批專用 `TEMP`／`TMP`／npm cache，不先安裝再搬。只驗本批與直接回歸，不做無關全量測試；完成後清理本批資源、分列通過／失敗／未執行／待確認並交付即停。
