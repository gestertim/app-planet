### 1.3 作品受眾、發布前提示與下架（Clarifications 第 5 題；OD-05；FR-013、FR-037）〔已批准；下架時限待定〕

| 畫面位置 | 設計 |
| --- | --- |
| 「發布」頁籤：學生主動選擇公開 | 提交公開申請的按鈕為學生主動操作；送出前以**必須確認**的提示說明：「持連結者不用登入就能打開，也可能轉傳給別人」「別人下載或截圖後，我們無法收回」「noindex 只降低被搜尋到的機會，不是不讓人打開」；並提示作品不得含可識別個人身分資訊與密鑰。未確認不得送出（措辭待教育者審閱，不是已審閱文案） |
| 「發布」頁籤：審查 | 教師／管理員審查清單含「作品及附帶資源（檔案、圖像、文字、設定）是否含可識別身分資料」；審查結果與理由保存 |

## 5. 創作空間首頁（UX-03）

### 5.1 畫面順序

問候與機器人夥伴 → 主要對話輸入框 → 中文標語 → 三張引導卡 → 六階段創作旅程 → 繼續我的創作。

### 5.2 三張引導卡〔新增行為〕

| 卡片 | 對應 Skill | 點擊結果 |
| --- | --- | --- |
| 我還沒有點子 | App 點子產生器 | 開始發想，逐步只問一個主要問題 |
| 我想開始做 App | AI App 超級創客 v5 | 從已知點子接續規格流程 |
| 我想學會新知識 | 萬能教師 | 確認主題並引導學習 |

- 可直接輸入，不強迫選卡；直接輸入時畫面顯示「未啟用特定 Skill」。
- 輸入中的文字與附件，在選卡、開啟工具、交接取消時保留；產生新對話後，未送出草稿不得無聲丟棄（須讓使用者選擇保留或放棄）。

### 5.3 六階段創作旅程〔新增行為〕

「點子 → 藍圖 → 設計 → 建立 → 測試 → 發射」為簡化進度摘要。

## 10. 版本、審查與發布（UX-08）

### 10.1 版本與恢復

恢復前先保存目前工作；快照保存失敗即停止恢復並提示原因與下一步；恢復後可再找回恢復前成果。

### 10.2 審查與部署

| 項目 | 設計 |
| --- | --- |
| 提交 | 固定不可變版本與內容雜湊；顯示「提交的是哪個版本」 |
| 教師審查 | 呈現該申請版本的藍圖、預覽、測試結果、變更及回饋；不得以目前工作預覽替代申請版；**並核對申請版及附帶資源是否含執行時呼叫生成式 AI 的程式或設定，含者退回修改**（2026-10-21 範圍決定，FR-049、FR-024；見 9.4） |
| 審查操作 | 「批准部署」「退回修改」（退回須填理由，保存後學生可重讀） |
| 修改後 | 須重新申請；工作區編輯不自動更新公開版本 |
| 成功網址 | 僅部署成功才顯示，且對應批准版；失敗保留原公開版 |

### 10.3 正式狀態（含「尚未提交」）

| 狀態標籤（文字必須同時呈現） | 說明 |

| 部署成功 | 顯示對應批准版網址 |
| 部署失敗 | 顯示失敗版本與下一步；保留原公開版本 |
