**信任邊界**：（1）瀏覽器不可信；（2）沙箱內學生程式不可信；（3）作品託管不可信內容；（4）OpenAI／Supabase／託管供應商為受條款約束的處理方（條件待核對）；（5）Worker 與 BFF 為受信任但**每步重驗**。

### 2. 學生登入碼與身分驗證（research.md R-01；contracts/auth-and-identity.md）
- **D-07a 狀態：已選首選驗證方案，附實測條件**（教育者 2026-10-21；不是已驗證可上線）。批准範圍僅限方案 A 的研究與設計方向；**未批准**技術驗證結果、登入碼長度／效期／限速數值、付費資源、Plan 定稿。
- 查證：Supabase Auth **無 username 登入**；管理 API（建立／改密碼／ban／撤銷／刪除）可用；**帳號維度限速不存在**（`/token` 僅 IP，預設 150 次／5 分；Password Verification Hook 僅 Teams／Enterprise）；停用後 JWT 到期前仍有效；官方 Admin signOut 需使用者有效 JWT（以使用者 id 全部撤銷的官方 API 本輪未查到）。
- **首選方案 A**：在既有 Supabase Auth 基線內，以**不代表真實學生電郵的合成電郵**作內部識別、登入碼作密碼；伺服器端把學生輸入的帳號對應至內部識別後代為登入，並做帳號×網路來源（HMAC 雜湊）節流；學生畫面只有帳號與登入碼，不收電郵或電話，不自設密碼。登入碼熵 ≥50 bits；一次顯示限最多一次伺服器秘密輸出機會，可能零次交付；重發成功新碼生效、舊碼立即失效，**不宣稱跨 Auth／平台 DB 原子回滾**；碼長／效期／限速為待決（D-07b～e，T1）。
- **D-32 四原則的分階段要求〔已批准／已同步，未實作〕**：原子性只限平台 DB 內可共同提交的版本／稽核／非秘密操作狀態；外部 Auth 不在該 transaction。區分未送出／可靠確認未套用、已確認套用及 unknown；已套用只向前恢復平台完成狀態，不重送 Auth／回滾外部密碼。unknown 不回成功、不保證舊碼可用，至少暫停以目標學生身分執行的受保護資料操作、新產品登入與平台 refresh。解除須有可審閱 terminal 或不再可能寫入的可靠證據，加上相依在途可信終結、舊 session 資料阻擋與平台完成證據；timeout／租約／DB generation／人工按鈕單獨不足，不盲重發。
- **秘密與權限邊界**：不存明文／可還原碼；同鍵同內容當下重驗資格，只回最小非秘密 receipt／狀態、不重播碼、不再次執行 Auth；異內容仍依 COMMON 拒絕，新鍵不得繞未結操作。輸出門閂先消耗再輸出，receipt 不授權或證明送達；記憶體秘密遺失只能依核准條件重新核身、新操作。保留教師／管理員合法授權、D-06(a)／M1／R-a、稽核與 account／school／ownership gate；暫停不改 disabled／學校／師生關係。教師獨立檢視、公開作品、跨角色／在途／背景委派細節仍待全路徑設計。
- **啟用阻擋**：unknown 可能長期不能安全收斂，不承諾自動恢復或未核定時限；可恢復性證據、供應商能力、具名主責／備援與支援安排、完整設計及正式驗收不足即不可啟用。M3 固定環境候選不等於產品採用，M2／hold／journal／dispatcher 未獲實作批准；schema／enum／API／HTTP／錯誤碼（含舊 502 的分支映射）、TTL／scope／cache／資料保存仍待決。[S-01-5／V-10](./quickstart.md#s-01-5-staged) 新驗收全部〔尚未執行〕，本批只文件同步，不結案任務／不通過 Gate。
- **實測條件（合成資料；全部〔尚未執行〕；設計見 quickstart §1.1）**：S-01 合成電郵相容性＋重發後舊登入碼失效；S-02 同校共用網路下的節流（`Sb-Forwarded-For`）＋登入錯誤不洩漏帳號是否存在；S-03 舊 access token／session 的資料層阻擋（停用、標記刪除、重發）。通過＝P1 進入條件。
- **若方案 A 驗證失敗**：保留替代方案 B（自驗＋magiclink）與 C（Clerk／Auth0 username；**更換已批准 Auth，須走憲章 III**）及其影響（research.md R-01），**交教育者重新決定；不自行改採、不自行更換 Auth 供應商**。
