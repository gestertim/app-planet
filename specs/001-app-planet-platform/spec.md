### Session 2026-10-26（A-9 四項契約原則；僅正式文件同步）

**批准紀錄〔已批准／已同步〕**：教育者本 session 明確批准 [D-32](./decision-register.md#d-32-a-9-已批准契約原則與必要正式文件同步2026-10-26台灣) 四原則及必要正式文件同步，授權見 [readiness §72](./readiness-review.md#72-2026-10-26-a-9-已批准契約原則的正式文件同步一次性文件授權先登錄)。保留故事 15／FR-051／SC-019／AC-21 的合法已綁定教師或管理員核身、成功後新碼生效／舊碼立即失效、不存可還原碼與稽核；「重發後」的成功承諾不能用來宣稱未完成／unknown 已成功或舊碼可用。D-06(a)／M1／R-a 與其他角色、school expired／ownership 政策不變。

撤除跨 Auth／平台 DB 的所有失敗回滾／保證舊碼可用承諾；未送出／可靠確認未套用、已確認套用、unknown 須如實區分（FR-026／038）。已確認套用只向前恢復，平台 DB rollback 不能撤銷外部 Auth；原子性僅涵蓋平台 DB 內可共同提交資料。unknown 不回成功，至少暫停以目標學生身分執行的受保護資料操作、新產品登入與平台 refresh；最小非秘密狀態／恢復入口仍受當下合法授權限制。暫停不等於 disabled，不改學校狀態或師生關係。解除前須有可審閱的原操作 terminal 或不再可能寫入的可靠證據，以及相依在途可信終結、舊 session 資料阻擋與平台完成證據；timeout、租約到期、DB generation、人工按鈕單獨均不足，不盲重發。

同鍵同內容仍當下重驗資格，只回最小非秘密 receipt／狀態，不重播秘密、不再次執行 Auth；同鍵異內容依既有拒絕規則，新鍵不得繞同目標未結操作。一次顯示是最多一次伺服器秘密輸出機會，可能零次交付，不保證恰好一次送達；receipt 不是授權或送達證明。記憶體秘密遺失後不能恢復原碼，只能依核准恢復條件重新核身、新操作。

四原則批准不等於流程啟用；unknown 可能長期不能安全收斂，不承諾自動恢復或未核定服務時限。供應商能力、完整設計、可恢復性證據、具名主責／備援與支援安排及正式驗收未齊仍阻擋。M3 僅固定環境候選、未採用；M2／hold／journal／dispatcher 未實作，新 schema／enum／API／HTTP／錯誤碼、TTL／scope／cache／在途／背景／跨角色與資料保存等未核定。本批不改任何 FR／US／AC／SC 編號或重做規劃，新增驗收全部〔尚未執行〕；G0／Checkpoint／完整 Gate 未通過、正式審議／簽核未執行、真實功能關閉。

**來源與效力**：教育者於本次對話明確批准下列範圍，依指令轉錄；無另附批准檔。此節是本功能現行 MVP 範圍。下方較早 Session、FR-048／FR-049 原 (3) 的 β2 句、US 14 情境 2／13／17、SC-016 與其他文件中「首版 A／B 含 β2」的批准與說明**保留為歷史，已被本次決定取代**；其餘未衝突的政策維持。這不是 Plan 定稿批准、Checkpoint 通過、Readiness Gate 通過或實作授權。

- **MVP 保留**：App Planet 平台 AI 對話、輔助創作與 Coding Agent；點子→藍圖→畫面→計畫→創作→測試→版本→審查→部署流程；A 級，以及**不需執行學生伺服器程式**的合格 B 級作品（含平台提供的受限 Work Data API）。B 級定義不改，不把此子集合宣稱為完整 B 級能力。
- **MVP 不提供**：學生伺服器程式的公開執行（B 級 β2）、作品執行時生成式 AI（C 級）、需訪客登入／帳號／蒐集可識別訪客資料的公開服務。β2 移至**後續獨立 feature**，另訂規格、配額、驗證與 Gate；不實作 M 或 W，不承諾開放日期；M 的 VC-3 僅留作研究證據。需 β2 的作品不能在 MVP 執行其伺服器功能，私人預覽亦不得暗中提供該執行路徑；可保留藍圖與檔案，提示改設計或待另立 feature，而非假裝可完整運作。
- **MVP 預覽（方案 X）**：Sandbox 以 `ports: []` 建置；平台取回、檢查並保存產物，右側 iframe 由平台控制的獨立來源提供互動預覽，**不是沙箱預覽埠反向代理**。更新為「儲存→重建→重載 iframe」，不提供開發伺服器 WebSocket／HMR。UI 顯示已保存版本、建置中／成功／失敗與目前預覽版本；保存成功不等於建置成功。失敗保留草稿、已保存內容與最後成功預覽（如有），明示舊版及原因／重試，不顯示假成功。
- **使用者看得到的限制**：藍圖、Agent、私人預覽、發布與指南均說明 MVP 支援的 A／B 子集合；需 β2 時顯示「MVP 不支援學生伺服器程式執行；後續獨立功能另訂」，公開提交被阻擋，不再使用「首版內尚在驗證、尚未開放」的承諾。既有需訪客識別的公開排除與作品不得呼叫 AI 的提示維持；學生端文案仍待適齡／專業審閱。預覽到期／撤銷、暫存資料不保留與已載入內容不可收回的限制維持。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 註冊、管理員批准與依角色存取 (Priority: P1)

學生、教師與管理員都必須先註冊，經管理員批准並核定角色後，才能使用受保護功能。待審核者只能查看申請狀態與登出；被拒絕者可查看結果與說明；被停用者不可使用受保護功能。使用者無法自行提升權限，隱藏按鈕不是唯一防線。

**Why this priority**: 平台服務 G4–6 兒童，所有功能都建立在「誰可以做什麼」之上；沒有可信的存取控制，其他故事都不能安全上線。

**Independent Test**: 以未登入、待審核、已拒絕、已停用、已批准的學生／教師／管理員帳號，逐一嘗試進入頁面並直接呼叫受保護操作，觀察結果是否與帳號狀態及角色一致。

**Acceptance Scenarios**:

1. **Given** 使用者剛完成註冊（學生為核發申請），**When** 登入，**Then** 帳號為「待審核」，僅看到申請狀態與登出，無任何受保護功能。
   - **Given** 學生帳號建立流程，**When** 檢視註冊資料，**Then** 不含真實姓名、電郵或電話；管理員角色無法經公開註冊取得。
2. **Given** 帳號為「已拒絕」，**When** 登入，**Then** 可看到拒絕結果與說明，且不能使用受保護功能。
3. **Given** 帳號為「已停用」，**When** 嘗試任何受保護操作（含背景工作進行中的重要步驟），**Then** 操作被阻擋且不洩漏他人資料。
4. **Given** 學生帳號，**When** 直接呼叫其他學生的專案、對話或檔案，或管理中心操作，**Then** 被拒絕；隱藏介面不是唯一防線。
5. **Given** 帳號在操作進行中被停用或降權，**When** 背景工作到達下一個重要步驟，**Then** 重新驗證後停止或拒絕該步驟。

### User Story 2 - 首頁引導、Skill 選擇與直接對話 (Priority: P1)

學生登入後看到正確的品牌標誌與三行品牌（AI APP 超級創客／App Planet／Chat. Create. Launch.）。首頁有三張引導卡：「我還沒有點子」「我想開始做 App」「我想學會新知識」，分別對應 App 點子產生器、AI App 超級創客 v5、萬能教師；學生也可以不選 Skill 直接輸入開始對話。首頁另有創作旅程摘要與最近專案續作入口。

**Why this priority**: 這是學生每次使用的第一個畫面，決定能否順利從點子進入創作。

**Independent Test**: 以已批准學生登入，點擊三張卡各一次、也直接輸入一段文字，確認每條路徑都能開始對話並清楚顯示啟用的 Skill（或無 Skill）。

**Acceptance Scenarios**:

1. **Given** 已批准學生進入首頁，**When** 查看畫面，**Then** 看到正確的 RAE 標誌與指定三行品牌，且品牌英文未被翻譯。
2. **Given** 首頁，**When** 點擊任一引導卡，**Then** 進入對應 Skill 的新對話，並清楚顯示啟用的 Skill。
3. **Given** 首頁，**When** 不選任何卡片直接輸入並送出，**Then** 可正常對話且顯示未啟用特定 Skill。
4. **Given** 學生尚無任何專案，**When** 查看首頁與「我的專案」，**Then** 顯示空白狀態與建立入口，而非固定示例作品。
5. **Given** 學生有多個專案與保存紀錄，**When** 查看創作旅程摘要，**Then** 階段進度由實際保存紀錄推導，而非固定已完成。
6. **Given** 輸入框已有未送出文字與附件，**When** 點擊任一引導卡或開啟「＋」工具，**Then** 文字與附件保留，且卡片依序帶出對應的起始流程（逐步只問一個主要問題／從已知點子接續規格／確認主題並引導學習）。
7. **Given** 首頁「繼續我的創作」，**When** 查看，**Then** 每項顯示專案名稱、摘要、實際階段與繼續入口，且創作旅程不使任何批准步驟被略過。

### User Story 3 - 對話管理、「＋」工具與草稿保護 (Priority: P1)

學生可建立獨立新對話、搜尋／重新命名／刪除自己的對話。輸入框內的「＋」依序提供：新增相片與檔案、從檔案庫加入、製作圖像、網頁搜尋。附件在送出前顯示名稱、處理進度、可用／失敗狀態並可移除。切換工具、關閉選單、離開頁面時，未送出的文字與附件不會無聲遺失。中文輸入法組字期間按 Enter 不會誤送。

**Why this priority**: 對話是學生與 AI 協作的主要介面；草稿遺失或誤送會直接傷害 G4–6 學生的創作信心。

**Independent Test**: 在輸入框輸入文字並加入附件，依序切換四項工具、開關選單、嘗試離開頁面，再以中文輸入法組字時按 Enter，確認內容保留且不誤送。

**Acceptance Scenarios**:

1. **Given** 任何時刻，**When** 建立新對話，**Then** 新對話不沿用不相關的舊脈絡。
2. **Given** 輸入框有未送出草稿，**When** 嘗試離開或切換對話，**Then** 系統保護內容並讓使用者選擇保留或放棄。
3. **Given** 開啟「＋」，**When** 查看選項，**Then** 依序為新增相片與檔案、從檔案庫加入、製作圖像、網頁搜尋，且四項皆可用。
4. **Given** 上傳超出格式或大小限制的檔案，**When** 驗證，**Then** 顯示失敗與原因，並可移除；限制數值依正式政策（見待決事項）。
5. **Given** 使用網頁搜尋成功，**When** 回答產生，**Then** 附上實際來源連結；失敗時顯示提示，不以固定示例冒充結果。
6. **Given** 製作圖像進行中，**When** 查看狀態，**Then** 顯示進度與可停止；成功後可預覽、保存至檔案庫並加入專案。
7. **Given** 使用中文輸入法組字，**When** 按 Enter 確認選字，**Then** 不會誤送訊息。
8. **Given** 選擇刪除對話，**When** 確認前，**Then** 說明影響，並確認另存專案與檔案庫內容不會被連帶刪除。
9. **Given** 附件處理中，**When** 查看輸入框，**Then** 顯示目前是否可送出及原因；**Given** 檔案庫為空或搜尋無結果，**Then** 顯示空白狀態與下一步入口。
10. **Given** 輸入框有未送出草稿，**When** 以 ⌘K／Ctrl+K 建立新對話，**Then** 草稿同樣受保護，並讓使用者選擇保留或放棄。
11. **Given** AI 回覆被使用者停止，**When** 查看訊息，**Then** 標明為部分輸出，既有內容保留，且每則訊息標示發話者與所用 Skill。

### User Story 4 - 創作引導與專案七頁籤 (Priority: P1)

學生由 AI 引導，依「點子 → A／B 作品等級（首版僅提供 A／B，不開發 C 級作品，2026-10-21 範圍決定）→ Specification → Checkpoint → Constitution → UX/UI → Specification Sync → Technical Plan → Final Pack」推進，每一步保留修改與批准紀錄。專案提供七個頁籤：我的藍圖、畫面設計、創作計畫、建立 App、測試、版本、發布，共用同一專案脈絡，任務狀態與編輯內容可保存。

**Why this priority**: 這是平台的核心價值——讓學生從點子走到可交付規格與計畫，且過程可追蹤。

**Independent Test**: 建立兩個專案，各自推進不同階段、編輯內容後登出再登入，確認各專案內容、階段與任務狀態各自保存且正確。

**Acceptance Scenarios**:

1. **Given** 新專案，**When** 完成各引導階段，**Then** 每階段保留修改紀錄與批准紀錄，並區分 AI 草案、已確認內容與正式批准版本。
2. **Given** 專案內，**When** 切換七個頁籤，**Then** 皆使用同一專案脈絡，且未保存的編輯不會靜默遺失。
3. **Given** 多個專案，**When** 切換專案，**Then** 各專案資料、階段與任務狀態各自獨立保存。
4. **Given** 專案內有修改任務狀態，**When** 保存失敗，**Then** 明確提示並保留可恢復草稿，不以提示訊息取代保存。
5. **Given** 有未保存內容，**When** 切換頁籤或專案，**Then** 先處理未保存內容，不靜默遺失。
6. **Given** AI 產出草案，**When** 學生尚未確認／批准，**Then** 草案不得被呈現為正式批准。
7. **Given** 創作引導的作品等級步驟（2026-10-21 範圍決定，Clarifications R1、FR-009），**When** 學生選擇等級，**Then** 只提供 A／B 兩個選項；不顯示可選的 C；等級依需求而非工具選擇，使用平台 AI 製作不使作品升級為 C。

### User Story 5 - 建立 App：IDE、Coding Agent 與可停止 (Priority: P2)

在「建立 App」頁籤，學生使用 IDE（檔案列表、程式編輯、保存、錯誤、預覽），並可選擇 Coding Agent 的兩種模式：「引導學習」逐步解釋、逐步確認；「自動開發」先呈現任務與影響並經確認，再按批准任務修改，並顯示進度、變更與結果。學生可隨時停止 AI 生成或 Agent，並看到已完成／未完成部分與恢復方式。

**Why this priority**: 這是學生實際產出 Web App 的環節，並以雙模式兼顧「學習」與「效率」。

**Independent Test**: 在同一專案分別以兩種模式執行一個修改任務並中途停止，比較行為差異、確認修改前已建立快照、停止後顯示部分結果。

**Acceptance Scenarios**:

1. **Given** IDE 中的檔案，**When** 編輯後尚未保存，**Then** 清楚辨識「編輯草稿／已保存內容／預覽版本」三者。
2. **Given** 引導學習模式，**When** Agent 提出修改，**Then** 逐步解釋並待學生確認後才執行下一步。
3. **Given** 自動開發模式，**When** Agent 提出計畫，**Then** 先呈現任務與影響並經確認，再僅執行已批准任務。
4. **Given** 任何重要修改前，**When** 開始套用，**Then** 先建立可恢復版本。
5. **Given** Agent 執行中，**When** 學生按停止，**Then** 顯示已完成與未完成部分及恢復方式，且不承諾已發生的外部費用可撤銷。
6. **Given** 保存時發生錯誤或網路中斷，**When** 失敗，**Then** 保留草稿並明確提示，不顯示假成功。
7. **Given** 預覽，**When** 查看，**Then** 標示「私人預覽／尚未公開」及所對應版本；AI 完成修改不被標為測試或審核通過。
8. **Given** 兩種 Agent 模式，**When** 執行同一任務，**Then** 行為實際不同（逐步確認 vs. 先呈現任務與影響再依批准任務執行），完成時皆顯示變更、測試結果與下一步。
9. **Given** 學生要求「讓我的作品自己呼叫 AI」（2026-10-21 範圍決定，Clarifications R2、R3），**When** 對話或 Coding Agent 收到此要求，**Then** 清楚說明首版不支援 C 級作品（作品不能在執行時呼叫生成式 AI），並可引導改為不依賴作品執行時 AI 的 A／B 設計；Agent 不得加入金鑰、前端直接呼叫 AI 服務或服務端 AI 呼叫，也不得以繞道方式達成；私人預覽不提供作品呼叫生成式 AI 的途徑。

### User Story 6 - 真實測試結果與版本恢復 (Priority: P2)

測試結果清楚區分「通過／失敗／未執行／待人工確認」，且綁定被測版本。學生可恢復到先前版本；恢復前系統必須先成功保存目前版本，保存失敗則不覆蓋現有工作。

**Why this priority**: 防止學生誤以為作品已測試正常，並讓犯錯可以安全回頭。

**Independent Test**: 讓部分測試未執行、部分需人工確認，確認不被標為通過；再於保存會失敗的條件下嘗試恢復，確認現有工作未被覆蓋。

**Acceptance Scenarios**:

1. **Given** 部分測試未執行或需人工確認，**When** 查看結果，**Then** 它們不被標為通過，且每筆結果標示所測版本。
2. **Given** 要恢復舊版本，**When** 目前版本成功保存，**Then** 才進行恢復，且之後可再找回恢復前成果。
3. **Given** 目前版本保存失敗，**When** 嘗試恢復，**Then** 不覆蓋現有工作並提示原因。

### User Story 7 - 提交審查與部署 (Priority: P2)

學生提交指定版本，由教師或管理員審查；狀態區分待審查、退回修改、已批准、部署中、成功、失敗。批准與部署申請綁定不可變版本與內容雜湊，審查預覽與測試對應申請版。批准後才部署，批准不等同部署成功；成功後顯示對應批准版的網址。學生之後編輯不會自動更新公開作品，需重新申請。

**Why this priority**: 這是「Launch」承諾的關鍵，同時涉及兒童作品公開，必須嚴格可控。

**Independent Test**: 提交 v1 後編輯成 v2，確認教師看到的仍是 v1 的預覽與測試，且僅 v1 能依該批准部署；再模擬部署失敗，確認不顯示成功網址且舊公開版保留。

**Acceptance Scenarios**:

1. **Given** 學生提交 v1，**When** 隨後把作品編輯成 v2，**Then** 教師仍看到 v1 的預覽與測試，僅 v1 可依該批准部署；審查畫面呈現該申請版的藍圖、預覽、測試結果、變更及回饋，不以目前工作預覽替代。
2. **Given** 已批准的申請，**When** 開始部署，**Then** 先顯示「部署中」，而非直接顯示成功。
3. **Given** 部署失敗，**When** 查看結果，**Then** 不顯示成功網址，且原公開版本保留。
4. **Given** 部署成功，**When** 查看結果，**Then** 網址對應批准版，且編輯後的新內容不會自動更新公開作品。
5. **Given** 教師退回修改，**When** 學生查看，**Then** 看到退回理由並可修改後重新申請。
6. **Given** 已部署作品的公開網址（受眾方案已於 2026-10-20 經教育者批准），**When** 未登入者持連結開啟，**Then** 可檢視，且設有 noindex、未列入平台公開目錄；noindex 不視為存取控制。**When** 教師、管理員下架或學生撤回後再開啟，**Then** 平台控制的公開網址、資源與服務在正式時限內停止存取（時限數值待決），且有稽核紀錄；不驗收已下載、截圖或外部副本的收回。
7. **Given** 學生在「發布」頁籤主動選擇公開並提交，**When** 送出前，**Then** 畫面須清楚提示：持連結者無須登入即可造訪、連結可能被轉傳、外部下載或截圖無法收回；學生確認後才能送出，未確認不得送出。
8. **Given** 教師或管理員審查公開申請，**When** 檢視申請版，**Then** 須檢視作品及附帶資源（檔案、圖像、文字、設定）是否含可識別身分資料，並可據此批准或退回；批准前不得部署。
9. **Given** 教師或管理員審查公開申請（2026-10-21 範圍決定，Clarifications R3），**When** 檢視申請版，**Then** 須同時核對作品與附帶資源是否含執行時呼叫生成式 AI 的程式或設定；含者退回修改、不得部署（首版不支援 C 級作品）。

### User Story 8 - 教師檢視、回饋與審查 (Priority: P2)

教師僅能查看管理員核定給自己的學生之專案、檔案、進度、完整對話、學習／開發紀錄與部署申請（可見範圍已於 2026-10-20 經教育者批准，僅於有效綁定期間授權），並可撰寫回饋與審查理由；重新開啟後內容一致。學生端於綁定期間常駐告知教師可查看的內容。

**Why this priority**: 教師是 G4–6 教學場域的把關者，需要可靠資料以指導與審查。

**Independent Test**: 以教師帳號查看獲授權與未獲授權學生，撰寫回饋後重新登入確認保存一致。

**Acceptance Scenarios**:

1. **Given** 教師帳號，**When** 查看學生清單，**Then** 只看到獲授權學生。
   - **Given** 管理員新增或解除師生綁定，**When** 保存，**Then** 教師可見範圍立即生效或失效，學生端綁定提示同步更新，並留稽核紀錄。
2. **Given** 教師存回饋或審查理由，**When** 重新開啟，**Then** 內容保持一致。
3. **Given** 教師直接以他人學生資源識別碼呼叫，**When** 未獲授權，**Then** 被拒絕。
4. **Given** 管理員解除師生綁定，**When** 教師之後再要求查看該學生資料，**Then** 新的存取立即被拒絕；**Given** 管理員於管理中心核對，**Then** 可查到教師的查看紀錄（已留稽核）。
5. **Given** 學生帳號被停用，**When** 該生當時已綁定的教師要求查看其專案、檔案、進度或對話，**Then** 被拒絕（查看權限於停用期間凍結）；教師仍可依停用當時保留的綁定紀錄提出受限的帳號複查，且僅能查看複查狀態與回覆（FR-052、FR-054）。**Given** 帳號被恢復，**Then** 師生綁定不自動恢復，須管理員重新綁定後教師才可再次查看。

### User Story 9 - 管理中心與稽核 (Priority: P2)

管理員在管理中心處理註冊審核、角色核定、師生關係、帳號狀態、額度與安全事件；所有變更保存並留有稽核紀錄。

**Why this priority**: 所有使用者都需管理員批准，是存取控制的運作中樞。

**Independent Test**: 批准／拒絕／停用帳號、調整師生關係與額度後重新開啟，確認一致且稽核紀錄存在。

**Acceptance Scenarios**:

1. **Given** 待審核申請，**When** 管理員批准並核定角色，**Then** 使用者下次存取依新狀態生效，並留稽核紀錄。
2. **Given** 管理員調整師生關係，**When** 保存，**Then** 教師可見範圍立即依新關係更新。
3. **Given** 非管理員，**When** 嘗試管理操作，**Then** 被拒絕並留安全事件紀錄。

### User Story 10 - Skill 切換與交接摘要 (Priority: P2)

在既有對話中切換 Skill 時，先出現可編輯的交接摘要（目標、已確認需求、資料引用、階段、未決事項），學生可確認或取消，原對話與草稿不變。Skills 在授權範圍內共用專案規格、檔案與進度；交接時重新檢查引用資料的權限。重新開啟對話時還原最後啟用的 Skill。

**Why this priority**: 三個 Skill 需要順暢協作，但不可因切換而遺失脈絡或越權。

**Independent Test**: 在有脈絡的對話中切換 Skill、修改摘要、確認／取消，檢查摘要內容來自當前脈絡而非固定示例；再重開對話確認最後 Skill。

**Acceptance Scenarios**:

1. **Given** 既有對話，**When** 切換 Skill，**Then** 先顯示由當前脈絡產生、可編輯的交接摘要。
2. **Given** 交接摘要，**When** 取消，**Then** 原對話與草稿完整保留、Skill 不變。
3. **Given** 摘要引用的檔案，**When** 使用者已無權限，**Then** 該引用被排除並提示。
4. **Given** 重新開啟對話，**When** 載入，**Then** 顯示最後啟用的 Skill。

### User Story 11 - 創作能量（用量）與額度 (Priority: P3)

使用者看到服務端用量、預留量及適用期間；未知時不顯示假數值。超限時阻止新增付費操作，但已保存內容仍可查看。並行與重試不造成超額或重複扣額。管理員可調整個人每日額度、各預算池分配及月度上限（調整留紀錄）。管理員的付費 AI 操作依用途歸池：平台內部學生／教師功能測試計入創作池（內部 AI 池）並有管理員測試額度；~~已部署公開作品的 AI 測試計入公開池及該作品上限~~【已被 2026-10-21 範圍決定取代・首版不適用：首版無公開作品 AI，公開池原規劃 US$150、首版不動用；原文保留作歷史】。

**Why this priority**: 控制費用風險，但可在核心流程之後完善。

### User Story 15 - 學生登入碼核發、登入與重發 (Priority: P1)

學生以「帳號＋系統核發登入碼」登入，不提供電郵或電話，也不自設密碼。教師或管理員發起帳號核發，帳號經管理員批准才生效。學生忘記登入碼時，由已綁定教師或管理員核對身分後重發；新碼生效使舊碼立即失效。登入嘗試須限速。（新增故事，來源：2026-10-20～21 PD-07 決策；對應 FR-051、FR-035、FR-045。）

**Why this priority**: 學生是 G4–6 兒童且不收個人聯絡資料，登入碼是唯一的學生憑證；沒有安全的核發與重發，學生無法進入平台，也無法維持最小個資原則。

**Independent Test**: 核發學生帳號並批准後以正確、錯誤、已被取代的登入碼各嘗試登入；以教師（已綁定、未綁定）與管理員嘗試重發；檢查管理畫面、日誌與稽核是否能讀到原碼；連續錯誤登入觀察限速。

**Acceptance Scenarios**:

1. **Given** 教師或管理員發起學生帳號核發，**When** 管理員批准前，**Then** 該帳號為「待審核」，不能使用受保護功能；批准後才可用登入碼登入（所屬學校核准狀態為「未確認／無紀錄」時仍不可登入，見 FR-046）。
2. **Given** 學生登入畫面與核發畫面，**When** 檢視，**Then** 只有帳號與登入碼，不含電郵、電話或學生自設密碼欄位。
3. **Given** 學生忘記登入碼，**When** 已綁定教師或管理員核對身分後重發成功，**Then** 新碼生效、舊碼立即失效，且重發留稽核；未完成／unknown 依 D-32 保持真實狀態與受控暫停，不宣稱成功或舊碼可用；**Given** 未綁定的教師嘗試重發，**Then** 被拒絕。
4. **Given** 登入碼已核發或重發，**When** 檢視管理畫面、稽核與日誌，**Then** 原碼無法被再次讀取，也不出現在日誌或稽核內容中。
5. **Given** 連續多次錯誤登入，**When** 超過限速規則，**Then** 後續嘗試被限速並顯示可理解的說明，不洩漏帳號是否存在；限速數值由 Plan 提案、教育者核定。
6. **Given** 碼長、效期與身分驗證供應商對無電郵學生帳號的支援方式，**When** 閱讀本規格，**Then** 這些項目標示為 Plan 技術研究，規格不宣稱任何供應商已原生支援「帳號＋登入碼」。

### User Story 16 - 帳號停用、恢復與刪除 (Priority: P2)

管理員可停用帳號：立即停止登入、新 AI 操作、新部署與待審申請處理，並使其公開作品停止公開，資料暫留供核對或恢復；學生帳號停用期間，教師查看該生專案與對話的權限凍結，但保留停用當時的綁定紀錄。首版不自動刪除停用帳號；管理員定期檢視、依學校結案、刪除請求及正式保存政策刪除。恢復不自動還原師生綁定與舊公開作品。刪除為「標記刪除並立即停止存取，再排程清除主資料與備份」。刪除須由管理員二次確認影響範圍才可啟動；恢復須顯示影響摘要並經一次明確確認；兩者均記錄操作者與時間。（新增故事，來源：2026-10-20～21 PD-03、PD-16 決策與 2026-10-21 補充決策；對應 FR-052。）

**Why this priority**: 兒童資料必須能被停止使用並依政策清除；停用與刪除也是公開作品生命週期的關鍵控制。

**Independent Test**: 對有公開作品、待審申請與師生綁定的學生帳號分別執行停用、恢復、刪除，並嘗試登入、AI 操作、部署與公開網址存取；停用期間以已綁定教師嘗試查看與提出帳號複查，恢復後再次嘗試查看；檢查刪除與恢復的確認步驟與紀錄、清除工作的完成與失敗紀錄，以及稽核對照的處理。

**Acceptance Scenarios**:

1. **Given** 帳號被停用，**When** 該帳號嘗試登入、新 AI 操作或新部署（含背景工作的下一個重要步驟），**Then** 被拒絕；其待審申請暫停處理，既有公開作品停止公開（時限數值依 OD-05，待核定），資料保留。
2. **Given** 帳號為已停用，**When** 檢查系統行為，**Then** 沒有任何「停用滿 N 天自動刪除」排程，也沒有其他未核定的自動刪除天數。
3. **Given** 管理員核對後恢復帳號，**When** 管理員發起恢復，**Then** 先顯示影響摘要（資料保留可用；師生綁定與舊公開作品不會自動恢復；要再公開須重新審查）並要求一次明確確認才執行，操作者與時間留稽核；恢復完成後資料保留可用，但師生綁定與舊公開作品**不自動恢復**；作品要再公開，必須重新走既有審查／部署流程。
4. **Given** 管理員要刪除帳號，**When** 發起刪除，**Then** 須先顯示影響範圍（立即停止存取、公開作品下架、待審及已批准未部署申請失效、資料排程清除），由管理員二次確認後才啟動，未完成二次確認不得啟動，操作者與時間留稽核；**When** 刪除標記建立，**Then** 立即停止登入與作業、公開作品下架、待審及已批准未部署申請失效；主資料與備份的清除以排程工作執行，並記錄工作的完成或失敗。
5. **Given** 清除工作失敗，**When** 管理員檢視，**Then** 可看到失敗紀錄與重試狀態，且該帳號仍保持不可存取（不因清除失敗而恢復存取）。
6. **Given** 主資料清除完成，**When** 檢查稽核資料，**Then** 「稽核代號→帳號」對照已移除，稽核事件可留至核定期限；文件與畫面不得稱其為完全匿名，且已檢查其他資源代號是否仍能識別學生並處理。
7. **Given** 停用帳號的檢視頻率、最長保留期限，以及主資料／備份清除天數與稽核保存期限，**When** 閱讀本規格，**Then** 這些項目標示為待核定（OD-11、OD-04），不默認永久保存。
8. **Given** 學生帳號被停用，**When** 該生當時已綁定的教師要求查看其專案、檔案或對話，**Then** 被拒絕（查看權限凍結）；停用當時的綁定紀錄被保留，且不因停用期間的查看要求而改變。
9. **Given** 學生帳號已被停用，**When** 停用當時已綁定的教師提出帳號複查，**Then** 依 FR-054(a) 以受限方式處理，教師僅能查看複查狀態與回覆，不取得任何學生資料。
10. **Given** 帳號被恢復，**When** 教師要再查看該生資料，**Then** 須由管理員重新綁定（FR-036）；未重新綁定前一律被拒絕。

### User Story 18 - 帳號複查與作品複查 (Priority: P3)

首版提供簡化複查流程：教師申請者（或發起核發的教師代提學生帳號）可就被拒絕的帳號提出帳號複查，由管理員處理；停用當時已綁定的教師，可依保留的綁定紀錄就被停用的學生帳號提出受限的帳號複查，僅可查看複查狀態與回覆；有效帳號學生可就特定作品版本的退回或下架，於「發布」頁提出作品複查，由原有審查權限的教師或管理員處理。複查不自動恢復帳號權限或公開作品。（新增故事，來源：2026-10-20～21 PD-04 決策與 2026-10-21 補充決策；對應 FR-054。）

**Why this priority**: 這是被拒絕或被退回／下架的使用者唯一的申訴管道，但可在核心流程之後完善。

**Independent Test**: 以被拒絕的教師帳號、被拒絕的教師核發學生帳號、有效學生（作品被退回與被下架）、已停用學生（由停用當時已綁定與未綁定的教師）各提出複查，檢查入口位置、授權、單一未結申請、回覆重讀，以及是否自動恢復任何權限或公開。

**Acceptance Scenarios**:

1. **Given** 教師申請者的帳號為「已拒絕」，**When** 在結果畫面提出帳號複查，**Then** 只能提交一件申請並讀取自己的狀態與回覆，不取得其他受保護功能。
2. **Given** 由教師核發而被拒絕的學生帳號，**When** 要提出複查，**Then** 由發起教師代提，對象為該學生帳號。
3. **Given** 有效帳號學生的作品版本被退回或下架，**When** 在「發布」頁提出作品複查，**Then** 申請綁定該作品版本，且僅限該學生本人的作品。
4. **Given** 已停用帳號，**When** 學生本人嘗試提出作品複查，**Then** 不提供此入口（停用帳號無法登入）；**When** 停用當時已綁定的教師要為該帳號提出複查，**Then** 依情境 10 提出受限的帳號複查（原「由已綁定教師向管理員反映」的歧義已更正：不是平台外或口頭管道，也不是作品複查）。
5. **Given** 同一處置已有未結申請，**When** 再提出，**Then** 被拒絕並說明；每次處置至多一件未結申請；已回覆的結果可重讀。
6. **Given** 複查申請送出，**When** 處理者處理並回覆，**Then** 申請紀錄含類型、對象、簡短理由、狀態、處理者、回覆與時間；帳號複查由管理員處理，作品複查由原有審查權限的教師或管理員處理，且逐次核對對象權限。
7. **Given** 任何複查，**When** 提出或回覆後，**Then** 帳號權限與公開作品**不自動恢復**；恢復須走既有的批准／審查／部署流程，並留稽核。
8. **Given** 大量或過長的申請，**When** 送出，**Then** 被限速與長度限制阻擋；處理時限與保存期限待核定。
9. **Given** 學生或教師要求個資查閱、更正或刪除，**When** 閱讀本規格，**Then** 這些請求不以作品複查或帳號複查取代，而是依 FR-056 的受理管道辦理（US 19）；家長／監護人的提出途徑未明示（OD-15）；處理與保存期限待核定。
10. **Given** 學生帳號已被停用，**When** 停用當時已綁定的教師提出帳號複查，**Then** 系統依保留的停用當時綁定紀錄核對其資格，並逐次核對該帳號仍為停用狀態；申請以該學生帳號為對象，教師僅能查看該申請的狀態與回覆，不得查看學生的專案、檔案或對話；每次處置至多一件未結申請，並受限速與長度限制；由管理員處理，且不自動恢復帳號權限。未曾於停用當時綁定的教師、或停用前已解除綁定的教師被拒絕。

### User Story 19 - 個資查閱、更正、刪除請求的受理 (Priority: P3)

學生、教師與無法登入者可透過已決定的管道提出個資查閱、更正或刪除請求：學生經學校既有聯絡管道或已綁定教師提出；教師經管理中心提出；無法登入者經學校既有管道提出。管理員記錄請求、核對提出者與處理權限，與學校確認處理方式後回覆。提出請求不會自動刪除資料，也不是帳號複查或作品複查。處理與保存期限待核定。（新增故事，來源：2026-10-21 補充決策，解決 OD-15 的受理管道；對應 FR-056。）

**Why this priority**: 兒童資料須有可行的查閱、更正與刪除管道；但可在核心流程之後完善。

**Independent Test**: 以學生（經學校管道、經已綁定教師）、教師（經管理中心）與無法登入者（經學校管道）各提出一次請求，檢查管理員的記錄、提出者與權限核對、與學校確認及回覆；確認提出請求後資料未被自動刪除；確認與帳號複查、作品複查的紀錄分開。

**Acceptance Scenarios**:

1. **Given** 學生要求個資查閱、更正或刪除，**When** 經學校既有聯絡管道，或經已綁定教師提出，**Then** 管理員記錄該請求；經已綁定教師提出者，須核對該教師具有效綁定。
2. **Given** 教師要求自己的個資查閱、更正或刪除，**When** 經管理中心提出，**Then** 請求被記錄；教師僅能查看自己請求的狀態與回覆，不因此取得管理中心的其他權限。
3. **Given** 無法登入者（例如帳號被停用、被拒絕或學校尚未確認而無法登入）要求，**When** 經學校既有管道提出，**Then** 管理員記錄該請求，並核對提出者與處理權限。
4. **Given** 管理員收到請求，**When** 處理，**Then** 須記錄請求、提出者核對結果、處理權限核對結果，與學校確認處理方式後回覆；各步驟的操作者與時間留稽核。
5. **Given** 請求已提出或已記錄，**When** 檢查資料，**Then** 資料**不會**因提出請求而自動刪除；若與學校確認的處理方式為刪除帳號，依 FR-052 的刪除程序（含管理員二次確認）執行；帳號以外資料項目的處理方式待核定。
6. **Given** 個資請求與帳號複查、作品複查，**When** 檢視紀錄與入口，**Then** 三者分開，不以複查取代個資請求，也不以個資請求取代複查（FR-054）。
7. **Given** 處理期限與保存期限，**When** 閱讀本規格，**Then** 這些項目標示為待核定（OD-15、OD-04），不填入數值；請求紀錄不保存不必要的個人資料（FR-043）。

### Edge Cases

- 帳號在操作進行中被停用、降權或被移除師生關係：下一個重要步驟必須重新驗證並停止。
- 上傳附件途中網路中斷或驗證逾時：顯示失敗、可重試或移除，不顯示假「可用」。
- 同一帳號多處同時編輯同一專案：不得靜默覆蓋，須提示衝突並保留雙方內容。
- 刪除對話時該對話引用的檔案已另存專案或檔案庫：被引用內容不連帶刪除。
- Skill 交接摘要引用的檔案在交接途中權限被撤回：引用被排除並提示。
- 提交審查後學生繼續編輯：審查與部署仍綁定提交的不可變版本，新的編輯須重新申請。
- 部署申請核准後、部署前，申請版本內容雜湊與批准時不符：必須拒絕部署並提示。
- 部署失敗、結果不明或逾時：不顯示成功網址，保留舊公開版，須核對實際結果。
- 額度剛好用盡時多個並行請求同時送出：不得超額；請求重試不得重複扣額。
- 外部網頁內容、使用者上傳內容或 Skill 內容嘗試指示 AI 提升權限或略過批准：不得生效。
- 網頁搜尋或圖像生成服務失敗：顯示可讀錯誤，不以示例內容代替。
- 恢復版本前保存失敗：不覆蓋工作，並提示原因與下一步。
- 中文輸入法組字、換行與 Enter 同時使用：不誤送，且換行保留。
- 學生離線或網路不穩：未保存內容保留於可恢復狀態，並如實顯示連線與保存狀態。
- 三個 Skill 的詳細指引尚未取得有權使用的可追溯來源：該 Skill 只能顯示已具備來源的能力，其餘標示「待取得」。
- 額度不足或頻率限制時：說明受影響操作，既有保存內容仍可查看，重試不重複扣額。
- 帳號、權限或師生關係在畫面已開啟時變更：更新可用操作與提示，不繼續未授權工作。
- 學校核准在學生使用 AI 功能期間被撤回或失效（含逾期）：下一個重要步驟重新驗證並停止；已保存內容仍按原有權限供登入者查看、編輯，新的公開部署暫停，該校既有非 AI 公開作品立即停止公開（FR-047；首版全部公開作品皆為不含作品執行時 AI 的 A／B 級作品；~~該校 C 級公開作品的 AI 呼叫停止~~為已被 2026-10-21 範圍決定取代的原文）；恢復核准後作品不自動公開，須重新審查及部署。
- 學校核准狀態為「未確認／無紀錄」：該校學生不得登入使用平台，管理員仍可辦理建校、核准及帳號準備（FR-046）；此與「撤回／失效」不同——後者的學生仍可登入並查看、編輯已保存內容，兩者不得混用。**教師（D-06 (a)，教育者 2026-10-23 決定）**：有效教師登入不依賴學校查詢；學校未確認時僅可使用受限的帳號準備範圍（帳號狀態、可取得的學校狀態、查看自己發起的申請狀態、為自己歸屬學校發起核發、首次領取自己發起之學生的登入碼；重發於學生學校未確認時拒絕），**不得**查看任何學生專案、對話、檔案或活動，亦不因此開放該校學生的 AI、審查或部署；學校資料讀取失敗時明示不可取得，不以未確認或預設值代替。教師可歸屬多所學校（由管理員建立／結束有效歸屬）。
- 被停用或標記刪除的帳號在背景工作進行中：下一個重要步驟重新驗證並停止，待審申請暫停處理；刪除排程清除失敗時，帳號仍保持不可存取（FR-052）。
- 帳號被恢復：師生綁定與舊公開作品不自動恢復；再公開須重新走審查／部署流程（FR-052）。
- 學生忘記登入碼：由已綁定教師或管理員核對身分後重發，成功後舊碼立即失效；未完成／unknown 依 D-32 受控暫停與恢復，不保證舊碼可用；原碼不可再被讀取、不入日誌（FR-051）。
- 內容安全自動判斷可能誤判或漏判：畫面與文件不得宣稱零誤判、全天監看或即時救援；高風險求助無可接收的綁定教師時改通知管理員（FR-053）。
- 值守邊界（2026-10-21 D-14 後續決定；以下為最小可驗收方案，**尚需教育者核定，不是已批准政策**，細節見 decision-register.md D-14）：非值守時段新增的學生 AI 請求被暫停（~~與公開 C 級 AI 請求~~，首版不適用）；值守時段結束時已在途的請求不被中途切斷、但不得續接新請求或新的重要步驟；未確認案件的計時只累計值守時間並跨時段保留；原收件者已是管理員而逾時，改標示並通知備援管理員；電郵失敗不改變處理狀態與計時；訪客事件逾時同樣依值守時段計算；值守或備援未設定時，AI 閘門維持關閉。
- 同一處置重複提出複查：每次處置至多一件未結申請，重複提出被拒絕（FR-054）。
- 已停用帳號的複查：學生本人無法登入，不提供作品複查入口；停用當時已綁定的教師可依保留的綁定紀錄提出受限的帳號複查，僅可查看複查狀態與回覆，不得查看學生資料（FR-054）。
- 學生帳號停用期間，教師查看其專案與對話的權限凍結；帳號恢復後綁定不自動恢復，須管理員重新綁定（FR-014、FR-052）。
- 管理員執行刪除但未完成二次確認，或執行恢復但未明確確認：操作不啟動，且不留下已執行的假象（FR-052）。
- **【已被取代・首版不適用（2026-10-21 範圍決定）；原文保留作歷史】** 公開 C 級作品的訪客輸入高風險內容：先顯示求助引導、避免生成有害內容，並建立最小安全事件紀錄通知平台管理員；不保存完整訪客輸入，不假設能識別訪客或對應綁定教師，不宣稱即時救援（FR-053(f)）。

- 個資查閱、更正、刪除請求已提出：不會自動刪除資料；須由管理員核對並與學校確認處理方式（FR-056）。
- 管理員調整額度或預算上限時，並行付費操作正在進行：新額度只對後續付費操作生效，進行中的預留與結算不被追溯改寫（FR-055）。
- 供應商端的實際用量或帳單與應用程式計量不一致，或供應商未提供硬性支出上限：不得宣稱已保證不超支；Plan 須區分應用程式計量、供應商支出提醒、可用硬性限制與無法保證的部分（FR-055）。
- **【已被取代・首版不適用（2026-10-21 範圍決定）；原文保留作歷史】** 公開 C 級作品的訪客在 AI 輸入欄輸入姓名、電話等個資：不主動蒐集，但仍可能被輸入並送至 AI 服務；告知、最小化、攔阻、保存與供應商處理方式見 OD-14，不宣稱「無任何個資」；訪客輸入高風險內容的處理見 FR-053(f)。

- 需要訪客登入、帳號或蒐集可識別訪客資料的 B 級作品被提交公開：被阻止並顯示首版排除說明，不得以靜態部署冒充完整 B 級支援。
- 學生要求或 Coding Agent 打算讓作品自己呼叫生成式 AI（2026-10-21 範圍決定，FR-049）：平台說明首版不支援 C 級作品並引導改為 A／B 設計；不得加入金鑰、前端直接呼叫或服務端 AI 呼叫；私人預覽與公開部署皆不提供途徑；審查發現含執行時 AI 呼叫者退回，不得部署。
- 學生使用平台 AI 製作 A／B 作品：不使作品升級為 C；平台 AI 的值守、額度、學校核准與內容安全閘門照常適用於學生的平台 AI 請求（FR-046、FR-053、FR-055）。

## Requirements *(mandatory)*

### Functional Requirements

**對話與工具**

- **FR-001**: 使用者必須能建立獨立新對話，不沿用不相關脈絡；離開未送出草稿前，系統必須保護內容。新對話的快捷鍵須依系統顯示（⌘K 或 Ctrl+K），經快捷鍵、選卡、開啟工具或取消 Skill 交接而產生或切換對話時，未送出的文字與附件同樣不得被無聲丟棄，須讓使用者選擇保留或放棄。
- **FR-002**: 使用者必須能查看、搜尋、重新命名及刪除自己的對話；「最近紀錄」只是摘要，仍須能查找全部已授權歷史。
- **FR-003**: AI 必須支援發想、釐清需求、解釋程式、排錯與測試規劃；回應須適合 G4–6，且草案不得呈現為正式批准。
- **FR-004**: 對話框內必須提供「＋」，依序包含：新增相片與檔案、從檔案庫加入、製作圖像、網頁搜尋；切換項目時保留草稿與附件。輸入框須支援多行文字、Enter 送出、Shift+Enter 換行；空白訊息不送出；模式標記可由使用者取消；框內須有 Skill 選擇。
- **FR-005**: 上傳附件在送出前必須顯示名稱、驗證／處理進度、可用／失敗狀態及移除操作；處理中須顯示目前是否仍可送出及原因；失敗時提供適當重試；格式與大小超限必須說明原因，限制依正式政策。
- **FR-006**: 使用者必須能從檔案庫搜尋、預覽並選擇有權存取的已保存檔案，加入目前對話；檔案庫為空或搜尋無結果時須有清楚的空白狀態與下一步入口。
- **FR-007**: 系統必須依描述生成圖像，顯示模式、進度及可停止狀態；成功結果可預覽、保存至檔案庫及加入專案；失敗或停止時不得產生假成功的結果項目。
- **FR-008**: 網頁搜尋必須呈現處理狀態；成功回答附實際來源連結，失敗有提示，不得以固定示例冒充結果。

**創作流程與工作區**

- **FR-009**: 創作引導必須依「點子、A/B（作品等級；首版僅 A／B，不提供 C，見 FR-049）、Specification、Checkpoint、Constitution、UX/UI、Specification Sync、Technical Plan、Final Pack」推進，並保留修改與批准紀錄。作品等級依需求而非工具選擇，使用平台 AI 製作不使作品升級為 C。**（2026-10-21 範圍決定：原步驟名稱為「A/B/C」，首版學生流程改為只提供 A／B 兩個選項；原文保留作歷史。）**
- **FR-010**: IDE 必須提供檔案列表、程式編輯、保存、錯誤及預覽，並可辨識編輯草稿、已保存內容與預覽版本。MVP 更新為「儲存→重建→重載 iframe」；必須顯示等待建置、建置中、成功或失敗及所對應版本，保存成功不代表預覽更新。建置／取回／檢查失敗時保留草稿、已保存內容及最後成功預覽（如有），明示舊版、原因與重試；沒有成功版本時顯示說明而非假成功。不提供 HMR 或學生伺服器程式執行。預覽須標示「私人預覽／尚未公開」並顯示所對應版本，不得被誤認為已發布。私人預覽**不提供學生作品呼叫生成式 AI 的途徑**（FR-049）。
- **FR-011**: Coding Agent 必須提供「引導學習」與「自動開發」雙模式，且兩模式須有實際不同的行為（不得僅切換選項）；前者逐步解釋並確認，後者先呈現任務、預計變更與影響並經確認，再依批准任務修改，並顯示進度、變更與結果。重要修改前須先保存快照；進行中可停止；完成須顯示變更、測試結果及下一步；AI 完成修改不得被呈現為測試或審核已通過。Agent 不得為學生作品加入金鑰、前端直接呼叫生成式 AI 或服務端 AI 呼叫；學生要求時依 FR-049 說明首版不支援 C 級作品並引導改為 A／B 設計。
- **FR-012**: 系統必須提供可理解的測試結果，區分通過、失敗、未執行及待人工確認，並說明原因與下一步；重要修改前必須建立可恢復版本。
- **FR-023**: 專案必須提供「我的藍圖、畫面設計、創作計畫、建立 App、測試、版本、發布」七個頁籤，使用同一專案脈絡（藍圖、任務、測試、快照與審查），任務狀態與編輯內容可保存。各頁籤的必要資訊如下：我的藍圖——目標、使用者、核心功能、A/B（首版不提供 C，FR-049）、驗收、版本及草案／已確認／正式批准，並可與 AI 討論修訂；畫面設計——頁面結構、畫面／流程、配色參考、預覽及設計狀態（學生作品配色與平台品牌配色分開）；創作計畫——任務、完成狀態、順序、驗收及批准，任務更新須實際保存，不得僅顯示提示訊息；建立 App——AI／Coding Agent、檔案與編輯器、作品預覽；測試——見 FR-012；版本——版本名稱或識別碼、時間、變更摘要與恢復入口；發布——檢查清單、申請版本、審查意見、部署進度、結果與成功網址。切換頁籤或專案前須處理未保存內容；保存失敗須明確提示並保留可恢復草稿。
- **FR-027**: 介面必須依畫面寬度調整工作區，可收合／切換對話、程式與預覽並放大預覽，不得硬擠三欄；窄畫面須提供可開啟的導覽，三個 Skills、專案、檔案庫與帳號仍須有入口，不得隱藏工具而無替代入口。

**審查、部署與版本**

- **FR-013**: 學生必須能主動選擇公開並提交指定版本，由教師或管理員審查批准後才部署；系統顯示審查與部署進度、結果及成功網址。已部署作品採公開網址（教育者已於 2026-10-20 批准，見 Clarifications 批准紀錄）：持連結者無須登入即可造訪，也可轉傳；平台須設定 noindex 並不主動列入公開目錄，noindex 只降低搜尋收錄，不提供存取控制。**發布前須清楚提示**：分享後可能被轉傳，以及外部下載或截圖無法收回；**審查須檢視作品及附帶資源中的可識別身分資料**。教師或管理員可下架、學生可自行撤回；下架或撤回後，平台控制的公開網址、資源與服務須依正式時限停止存取（時限數值待決，見 OD-05）並留稽核紀錄，學生可重新提交；平台不承諾收回已下載、截圖或外部副本。公開作品不得包含學生可識別個人身分資訊與密鑰。A／B 級作品的公開範圍見 FR-048；首版不含 C 級作品（FR-049、FR-050 已由 2026-10-21 範圍決定取代，原條文保留作歷史）。
- **FR-024**: 部署申請及批准必須綁定不可變版本與內容雜湊；審查預覽及測試必須對應申請版；教師審查須呈現該申請版的藍圖、預覽、測試結果、變更及回饋，不得以目前工作預覽替代；審查操作為「批准部署」與「退回修改」，退回理由須保存並可由學生重新讀取；修改後必須重新申請；編輯不得自動更新公開作品。審查另須核對申請版是否含作品執行時呼叫生成式 AI 的程式或設定，含者退回修改（FR-049）。
- **FR-025**: 恢復前必須成功保存目前版本；保存失敗不得覆蓋工作。部署失敗必須保留原公開版本。
- **FR-032**: 審查與部署必須區分：尚未提交、待審查、退回修改、已批准、部署中、成功、失敗（「尚未提交」為提交前的起始狀態）；各狀態須以文字呈現，不得只靠顏色；批准不得直接等同部署成功，成功網址必須對應批准版，失敗不顯示成功網址。

**教師與管理**

- **FR-014**: 教師必須能查看獲授權（已綁定）學生的專案、檔案、進度、完整對話、學習／開發紀錄、回饋及部署申請，供教學與安全目的使用（可見範圍已於 2026-10-20 經教育者批准）。授權僅於有效綁定期間成立，綁定即時生效、解除即時失效並停止新的存取；學生帳號被停用期間，教師對該生專案與對話的查看權限**凍結**（停用當時的綁定紀錄保留，見 FR-052），恢復帳號後須由管理員重新綁定才可再次查看；不得擴張為所有教師都能查看所有學生（FR-036）。綁定期間學生端必須持續、清楚地顯示「老師可查看哪些內容」；教師對學生資料的查看須留稽核紀錄，**管理員可於管理中心核對**；此可見範圍須納入學校對學生／監護人的告知內容（FR-046）。回饋可保存並重新讀取。
- **FR-015**: 管理中心必須能管理註冊申請審核、角色、師生關係、帳號停用與狀態、額度、安全事件、個資請求受理（FR-056）及操作紀錄；變更（含教師回饋、審查理由與師生綁定變更）須實際保存、可重新讀取且有稽核。

**Skills 與 AI 控制**

- **FR-016**: 系統必須內建 AI App 超級創客 v5、App idea generator（顯示為「App 點子產生器」）、萬能教師；新舊對話皆可選擇，新對話選定 Skill 後須清楚顯示啟用項目。
- **FR-017**: 既有對話切換 Skill 時，必須先提供可編輯的交接摘要，列出目標、已確認需求、資料引用、階段及未決事項；可確認／取消，並保留原對話與草稿。
- **FR-018**: Skills 必須在授權範圍內共用專案規格、檔案與進度；交接時重新檢查引用資料的權限；摘要不得套用固定示例。
- **FR-019**: 系統必須區分 AI 草案、已確認內容與正式批准版本，且對話訊息須標示發話者及所使用的 Skill；Skills 不得自行取得或宣告批准。
- **FR-020**: Skills 必須共用平台角色、權限、安全與額度，不得提升權限。
- **FR-021**: 使用者必須能停止 AI 生成與 Agent；停止後須標明部分輸出並保留既有內容，顯示已完成／未完成部分及恢復選擇，且不承諾已發生的外部費用可撤銷。
- **FR-022**: 刪除對話前必須說明影響；另存的專案及檔案庫內容不得連帶刪除。

**狀態真實性與首頁**

- **FR-026**: 保存、連線、附件、AI、Agent 與部署必須呈現真實狀態；失敗時保留可恢復內容，不得以假成功或固定「已保存」狀態代替。有未保存修改須顯示；保存失敗或離線須保留草稿、提示原因並提供手動重試；AI／Agent 中斷須保留已完成部分、列明未完成項目並提供恢復選擇；額度不足或頻率限制須說明受影響的操作，且既有保存內容仍可查看；帳號或權限變更後須更新可用操作與提示，並不得繼續未授權工作；進度與錯誤須可被輔助工具讀取（見 FR-034）。
- **FR-028**: 首頁必須提供三張引導卡：「我還沒有點子」「我想開始做 App」「我想學會新知識」，分別對應三個 Skills（App 點子產生器、AI App 超級創客 v5、萬能教師）；點擊後依序為：開始發想並逐步只問一個主要問題、從已知點子接續規格流程、確認主題並引導學習。也可不選 Skill 直接對話，並顯示未啟用特定 Skill；選卡、開啟工具時輸入中的文字與附件須保留（見 FR-001、FR-031）。
- **FR-029**: 首頁必須提供創作旅程摘要及「繼續我的創作」；旅程以「點子、藍圖、設計、建立、測試、發射」為簡化進度摘要，進度由實際保存紀錄推導，不得固定亮起某一階段，且不得取代 FR-009 的引導步驟與批准（Constitution、規格同步、計畫、任務與審查不得因旅程未列出而跳過）；「繼續我的創作」須顯示專案名稱、摘要、實際階段與繼續入口。「我的專案」須顯示真實專案列表並可進入專案詳情，無專案時提供開始創作入口，不得顯示固定示例作品或預造已完成藍圖。頂部資訊列須顯示目前頁面／對話／專案、適用時的當前 Skill、真實保存狀態，並提供「使用指南」入口（內容待定，見 OD-08）；「互動模擬」標示僅限展示環境。
- **FR-030**: 創作能量必須顯示服務端用量（剩餘或可用）、預留及適用期間（每位學生每日額度，於 Asia/Taipei 每日 00:00 重置）；為用量資訊，不得做排行榜或催促消耗；未知時顯示「未知」，不得顯示假數值。超限須阻止相應的新增付費操作並說明受影響操作與原因（個人每日額度，或所屬預算池的月度上限；預算池見 FR-042、FR-055），但已保存內容仍可查看；管理員可調整個人每日額度、各預算池分配及月度上限（含臨時加額），每次調整須依 FR-055 記錄並留稽核。
- **FR-031**: 重新開啟對話必須還原最後啟用的 Skill（而非第一則訊息的 Skill）；切換工具／頁面／Skill 時，必須保護文字、附件及未保存工作，避免靜默遺失；取消 Skill 交接時須保留原 Skill、草稿與原對話。
- **FR-033**: 正式版必須只顯示已授權角色能力，帳號區只提供已授權身份及操作；示範角色切換、固定學生資料、假結果與本機示範狀態不得作為正式權限或保存機制，亦不得以顯示或隱藏導覽代替後端授權。
- **FR-034**: 介面必須支援鍵盤操作、可見焦點、具名圖示按鈕、彈窗焦點管理（開啟時焦點移入並限制於彈窗內、關閉回到觸發點、可取消彈窗可用 Esc 關閉）、可讀狀態（進度與錯誤可被輔助工具讀取）及非顏色提示；一般文字對比至少 4.5:1、大字至少 3:1；支援中文組字與換行（Enter 送出、Shift+Enter 換行），避免 Enter 誤送。

**帳號、權限與安全（來自帳號／安全約束）**

- **FR-035**: 所有使用者（學生、教師、管理員）必須先註冊（學生為管理員或教師發起的核發申請）並經管理員批准；學生以不收電郵、電話的匿名暱稱帳號，使用「帳號＋系統核發登入碼」登入，**不由學生自設密碼**（登入碼規則見 FR-051；2026-10-21 教育者決定，取代原「帳號＋密碼或登入碼」），教師與管理員使用電郵＋密碼登入；帳號狀態為「待審核、已批准、已拒絕、已停用」，各狀態須有明確畫面。待審核只能查看申請狀態及登出；已拒絕可查看結果與說明，並可依 FR-054 提出帳號複查；已停用不得使用受保護功能（停用的完整行為見 FR-052；停用當時已綁定的教師可依 FR-054 提出受限的帳號複查）。學生帳號即使已批准，仍須所屬學校核准狀態不是「未確認／無紀錄」才可登入（FR-046）。申請的角色不等於取得權限。
- **FR-036**: 角色與師生關係必須由管理員核定；使用者不得自行提升權限。學生僅管理自己的資料；教師僅查看已綁定學生的資料（範圍見 FR-014）與審查；管理員管理平台。學生帳號停用後恢復，師生綁定不自動恢復，須由管理員重新核定（FR-052）。
- **FR-037**: 專案、對話與檔案預設為私人（相對於其他學生與未綁定者；已綁定教師依 FR-014 可見）；公開必須走授權流程（部署批准，受眾見 FR-013）。
- **FR-038**: 每次受保護操作都必須驗證即時帳號狀態、角色與資源權限；背景工作開始及各重要步驟也必須重新驗證；隱藏介面不得作為唯一防線。
- **FR-039**: 密鑰不得出現在前端、學生作品、下載檔或紀錄中。
- **FR-040**: 不受信任的程式必須在隔離環境執行，並限制資源、時間、工具及網路；作品預覽必須與平台主介面相互隔離。

- **Agent 任務**：Coding Agent 的任務、模式、批准狀態、進度、變更與結果。
- **審查與部署申請**：綁定特定不可變版本；狀態為待審查、退回修改、已批准、部署中、成功、失敗；含理由與成功網址。
- **回饋**：教師對學生專案的意見，可保存並重新讀取。
- **用量／額度紀錄**：預留、執行、結算與釋放的記錄，含適用期間、所屬預算池與限制。
- **稽核與安全事件紀錄**：管理、Agent、部署及權限拒絕等操作的追溯紀錄；以內部代號連結，清除主資料時移除代號→帳號對照（FR-052），不稱完全匿名。
